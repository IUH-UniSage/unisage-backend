# 0002: Cơ sở dữ liệu (backend-java)

- **Ngày**: 2026-08-22
- **Phạm vi**: Tham chiếu chi tiết cột, kiểu dữ liệu, ràng buộc và chỉ mục của từng bảng PostgreSQL, ánh xạ từ thực thể JPA trong `src/main/java/com/unisage/backend/entity/`.
- **Xem trước**: [0001-erd.md](./0001-erd.md) mô tả quan hệ tổng thể giữa các bảng; tài liệu này đi sâu vào từng bảng.

## Quy ước chung

- Mọi bảng kế thừa `BaseEntity` đều có 5 cột kiểm toán giống nhau, không lặp lại ở từng bảng bên dưới trừ khi có ngoại lệ:

  | Cột | Kiểu | Ghi chú |
  |---|---|---|
  | `id` | UUID | Khoá chính, sinh tự động (`@GeneratedValue(generator = "UUID")`), `NOT NULL`, không cập nhật được sau khi tạo. |
  | `created_at` | TIMESTAMP | Gán tự động lúc tạo (`@CreatedDate`), không cập nhật được. |
  | `created_by` | VARCHAR | Người/tiến trình tạo bản ghi (`@CreatedBy`), không cập nhật được. |
  | `updated_at` | TIMESTAMP | Tự động cập nhật mỗi lần sửa (`@LastModifiedDate`). |
  | `updated_by` | VARCHAR | Người/tiến trình sửa gần nhất (`@LastModifiedBy`). |
  | `is_active` | BOOLEAN | Mặc định `true`. Riêng bảng `users` **không dùng** cột này để biểu thị trạng thái hoạt động — xem mục Users bên dưới. |

- Hai bảng nối thuần (`role_permissions`, `user_department_access`) **không** kế thừa `BaseEntity` — không có `id` riêng, không có 5 cột kiểm toán ở trên; khoá chính là khoá tổ hợp của hai khoá ngoại.
- "Xoá mềm": các bảng có cột `deleted_at` (`conversations`, `departments`, `documents`, `users`) đánh dấu bản ghi đã xoá bằng cách gán timestamp thay vì xoá vật lý (`DELETE`).

## `permissions`

| Cột | Kiểu | Ràng buộc |
|---|---|---|
| `name` | VARCHAR(100) | `NOT NULL` — vd `USER_READ` |
| `path` | VARCHAR(255) | `NOT NULL` — mẫu Ant-style path của endpoint được bảo vệ |
| `method` | VARCHAR(10) (enum `PermissionMethod`) | `NOT NULL` — `GET \| POST \| PUT \| PATCH \| DELETE \| ALL` |
| `resource_type` | VARCHAR(50) (enum `ResourceType`) | `NOT NULL` — phân loại tài nguyên (nhãn tiếng Việt, vd "Tài liệu") |
| `description` | VARCHAR(255) | |
| `access_level` | INTEGER | Mặc định `NULL` |

**Chỉ mục**:
- `idx_permission_path_method` trên `(path, method)` — tra cứu nhanh khi kiểm tra một request cụ thể có permission tương ứng hay không.
- `idx_permission_name` trên `(name)`.

Được tham chiếu (nhiều-nhiều với `roles`) qua bảng nối `role_permissions`.

## `usage_limits`

| Cột | Kiểu | Ràng buộc |
|---|---|---|
| `user_id` | UUID | FK → `users.id`, **nullable** — khách vãng lai theo dõi qua `ip_address` |
| `ip_address` | VARCHAR | |
| `limit_type` | VARCHAR (enum `UsageLimitType`) | `MESSAGE \| TOKEN \| IMAGE \| API` |
| `scope` | VARCHAR (enum `UsageLimitScope`) | `DAILY \| WEEKLY \| MONTHLY` |
| `scope_date` | DATE | Ngày mốc của chu kỳ giới hạn (vd đầu tuần/đầu tháng tuỳ `scope`) |
| `used_count` | INTEGER | Mặc định `0` |
| `last_used_at` | TIMESTAMP | |

**Ràng buộc duy nhất (unique constraint)** — hai ràng buộc song song, đảm bảo mỗi định danh (user hoặc IP) chỉ có một bản ghi giới hạn cho mỗi tổ hợp loại/chu kỳ/ngày mốc:
- `(user_id, limit_type, scope, scope_date)`
- `(ip_address, limit_type, scope, scope_date)`

| `last_login` | TIMESTAMP | |
| `deleted_at` | TIMESTAMP | Xoá mềm |

> **Ngoại lệ so với `BaseEntity`**: cột `is_active` kế thừa từ `BaseEntity` **không được dùng** để biểu thị trạng thái hoạt động của người dùng. Getter `isActive()` bị override thành `@Transient` (không map cột riêng, luôn tính lại) trả `status == UserStatus.ACTIVE`; setter là no-op. Nói cách khác, trạng thái hoạt động của user luôn suy ra từ cột `status`, không đọc/ghi trực tiếp cột `is_active` trong bảng `users`.

Được tham chiếu từ `conversations.user_id`, `documents.ingested_by`, `usage_limits.user_id` (đều nullable), và (nhiều-nhiều với `departments`) qua `user_department_access`.

## Danh sách đầy đủ các enum (lưu dưới dạng `VARCHAR` qua `@Enumerated(EnumType.STRING)`)

| Enum | Giá trị | Dùng ở cột |
|---|---|---|
| `DocStatus` | `PENDING, PROCESSING, COMPLETED, FAILED, OUTDATED` | `documents.status` |
| `MsgRole` | `USER, ASSISTANT, SYSTEM` | `messages.role` |
| `MsgStatus` | `PENDING, STREAMING, COMPLETED, ERROR` | `messages.status` |
| `PermissionMethod` | `GET, POST, PUT, PATCH, DELETE, ALL` | `permissions.method` |
| `ResourceType` | `USER, ROLE, PERMISSION, DEPARTMENT, USER_DEPARTMENT_ACCESS, DOCUMENT, CATEGORY, ACCESS_LEVEL, CHAT_MODEL, LLM_TRACE_LOG, INGEST, CONVERSATION, MESSAGE, AUDIT_LOG, SYSTEM, OTHER` | `permissions.resource_type` |
| `UsageLimitScope` | `DAILY, WEEKLY, MONTHLY` | `usage_limits.scope` |
| `UsageLimitType` | `MESSAGE, TOKEN, IMAGE, API` | `usage_limits.limit_type` |
| `UserStatus` | `ACTIVE, INACTIVE, BANNED` | `users.status` |

`AllowedFileType` (`TXT, PDF, DOCX, DOC`) **không** nằm trong danh sách trên vì nó không map tới cột nào — chỉ dùng để kiểm tra tại tầng ứng dụng khi upload file lên MinIO (xem `docs/adr/0001-document-file-upload-validation-policy.md`).
